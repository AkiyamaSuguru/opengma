# 开发流程

## 开发环境

需要 Python 3.14 和 [uv](https://docs.astral.sh/uv/)。在仓库根目录：

```bash
uv sync
```

`uv sync` 建立 `.venv`，以可编辑模式安装 `GMA`（src 布局，构建后端 uv_build，`module-name = "GMA"`），并安装三组依赖：

| 依赖 | 位置 | 内容 |
| --- | --- | --- |
| 运行依赖 | `[project].dependencies` | flet、flet-charts、numpy、pandas、matplotlib、plotly、xarray、h5netcdf、openpyxl、python-calamine。打包时只打包这一组 |
| `dev` 组 | `[dependency-groups]` | flet-cli（打包）、flet-desktop（桌面窗口）、flet-web、flet[test]、pytest |
| `notebook` 组 | `[dependency-groups]` | marimo |

`dev` 和 `notebook` 都是默认安装的组（`[tool.uv] default-groups`）。只想用库、不装 marimo 时：`uv sync --no-group notebook`。增加依赖时注意放在哪一组：GMA 运行时用到的放进 `[project].dependencies`，只在开发时用到的放进 `dev`，否则会被打包进程序或者漏掉。

## 运行

```bash
uv run opengma                 # 图形界面（入口 GMA.UI:run）
uv run python -m GMA.UI        # 同上
uv run python scripts/ui_p2/demo_project.py   # 生成演示项目 scripts/ui_p2/演示项目.nc（模拟数据）
uv run marimo edit             # marimo 笔记本中把 GMA 当作库使用
```

几个环境变量：

| 变量 | 作用 |
| --- | --- |
| `OPENGMA_HOME` | 设置、自动备份所在的文件夹，默认 `~/.opengma`。测试和自检都把它指向临时文件夹，不碰自己的设置 |
| `OPENGMA_SMOKE_TEST` | 自检结果文件的路径。设置后程序打开启动器，检查项目文件、Excel、出版图、SRIM、熔盐计算，写出结果后退出（`GMA/UI/services/smoke.py`） |
| `OPENGMA_NEW_WINDOW` | 内部使用：“新建窗口”启动的进程从启动器开始，不打开上次的项目 |

调试界面、截图时，可以让 Flet 以网页模式运行，再用浏览器或 Playwright 打开（网页中的文件对话框拿不到文件路径，所以导入要另外处理）：

```python
import flet as ft

from GMA.UI import strings
from GMA.UI.settings import load_settings

strings.use(load_settings().language)   # 先选界面语言，再导入界面模块
from GMA.UI.app import ASSETS, main     # noqa: E402

ft.run(main, view=ft.AppView.WEB_BROWSER, port=8550, assets_dir=str(ASSETS))
```

## 测试

```bash
uv run pytest
```

| 文件 | 测什么 |
| --- | --- |
| `tests/conftest.py` | 共用的测试数据：用高斯峰合成的 XPS、Raman、XRD 谱和拟合谱，生成 Avantage、Horiba、Bruker 格式的文件 |
| `test_loaders.py`、`test_plotting.py`、`test_xps_analyzer.py` | CM：读取、出版图和交互图、XPS 分析 |
| `test_project.py`、`test_project_io.py`、`test_project_tables.py` | project：数据模型与清洗、导入导出、NetCDF 读写、峰位表与通用表格 |
| `test_sc.py` | SC：SRIM（`tests/data/srim` 中按 TRIM 格式合成的 Quick K-P 文件，以及测试中手写的 Full Cascade、多层靶）和熔盐配比，并与原来的参考脚本对比 |
| `test_ui_core.py`、`test_ui_p3.py`、`test_ui_p4.py`、`test_ui_p5.py` | 界面中不需要窗口的部分：设置、会话、适配层、出版图与复制为代码、计算工具页的计算、自动备份、项目锁、中英文文字、打包配置 |

界面相关的测试都不打开窗口：适配层（`GMA/UI/services`）不导入 flet，可以直接测；页面中的计算部分用一个只有设置和配色的替身对象测。界面的样子在网页模式下截图检查，桌面版再用自检确认能启动。新功能都应该带测试，测试不依赖网络和本机的字体、设置。

## 代码约定

- **文件头**：每个文件开头两行 SPDX 声明：`# SPDX-FileCopyrightText: 2026 Jay Ma` 和 `# SPDX-License-Identifier: AGPL-3.0-only`。
- **语言**：说明文字（docstring、注释、文档）用中文，标识符用英文。库中抛出的异常信息用英文，说明哪个文件、哪一步、为什么；界面上看到的文字全部来自 `GMA/UI/strings.py`（中文）和 `strings_en.py`（英文），见 [UI 模块 · 界面文字与翻译](UI模块.md#界面文字与翻译)。
- **三个系统通用**：不写按系统区分的分支。路径用 `pathlib`；读写文本文件写明 `encoding="utf-8"`（中文 Windows 的默认编码不是 UTF-8）；时间带时区（`datetime.now(UTC)` 或 `.astimezone()`）；启动子进程不用 shell。
- **依赖单向**：`GMA.CM`、`GMA.SC`、`GMA.project` 和 `GMA.UI.services` 不导入 flet。
- **数据优先**：界面上的修改先改项目（`GMA.project`），再刷新界面；归一化、错开等显示设置不修改数据。
- **不预设领域知识**：不内置峰位、化学键、物相；熔盐的内置组成只是可以修改的起点。
- **检查代码**：`ruff check src tests`。仓库没有固定的 ruff 配置；`CM`、`XPS` 这样的大写包名是有意的，N999 的提示可以忽略。

## 分支、提交与 PR

- 每项改动开一个分支，提 PR 到 `main`，由作者决定是否合并（Q15）。图形界面分 P0–P5 六个 PR 完成，可以在 PR 中看到每个阶段的说明和测试情况。
- 提交信息用英文：第一行用祈使句概括改了什么，空一行后说明原因和要点。
- 不提交生成的文件：`build/`、`dist/`、打包时复制的 `src/assets/`、演示项目都已在 `.gitignore` 中。
- 版本号写在 `pyproject.toml` 的 `[project].version`，“关于”对话框从安装信息中读取。

## 打包

图形界面用 [flet build](https://flet.dev/docs/publish) 打包成带 Python 的程序，三个系统用同一个脚本：

```bash
uv run python scripts/build_app.py build macos     # 或 windows、linux，只能在对应的系统上打包
uv run python scripts/build_app.py smoke macos     # 运行打包好的程序做一次自检
```

- **配置**：`pyproject.toml` 的 `[tool.flet]`（程序名 OpenGMA、组织、版权）和 `[tool.flet.app]`（打包 `src` 文件夹，入口 `src/main.py`）。打包的 Python 版本按 `requires-python` 选（3.14），依赖取自 `[project].dependencies`。
- **资源**：打包的程序从应用文件夹中的 `assets` 读取图标和字体，所以脚本先把 `src/GMA/UI/assets` 复制到 `src/assets`，打包后删除。`icon.png`（Windows、Linux）和 `icon_macos.png`（按苹果的图标网格）是应用图标，由 Logo 生成。
- **产物**：`build/<系统>/` 中是程序，`dist/` 中是压缩包（Mac 用 ditto 保留 .app 的元数据，Linux 用 tar.gz 保留可执行权限）。
- **自检**：`smoke` 去掉开发环境的痕迹（虚拟环境、`PYTHONPATH` 等），用 `OPENGMA_SMOKE_TEST` 运行程序，读取结果。结果中有程序用的 Python、可执行文件和 numpy 的位置，可以确认程序用的是自己带的 Python。
- **各系统需要的工具**：Mac 上 Xcode 15 以上、CocoaPods 1.16 以上，Apple 芯片还需要 Rosetta；Windows 上 Visual Studio 2022（使用 C++ 的桌面开发）；Linux 上的系统软件包见 `uv run flet --version --json` 中的 `linux_dependencies`。第一次打包时 flet 会把 Flutter SDK 下载到 `~/flutter`。

### GitHub Actions

`.github/workflows/build-app.yml` 在 GitHub 的 macOS、Windows、Linux 机器上各打一个包，上传压缩包，再运行自检。触发方式：

- 手动：Actions → Build desktop app → Run workflow；
- 推送 `v*` 标签，如 `git tag v0.2.0 && git push origin v0.2.0`；
- 修改打包相关文件（这个 workflow、`scripts/build_app.py`、`src/main.py`、`GMA/UI/services/smoke.py`）的 PR。

打包失败或自检失败时，脚本把出错的最后几十行写成运行结果中的注释（annotation），在运行页面的摘要中就能看到；自检通过时也会写一条注释，列出程序用的 Python 和可执行文件。打好的包在运行页面的 Artifacts 中下载。提交信息中写 `[skip ci]` 时这次推送不触发 workflow，只改文档时可以用。

程序没有签名。第一次在 Mac 上打开下载的程序要在“系统设置 → 隐私与安全性”中点“仍要打开”；正式分发需要 Apple 的 Developer ID 签名与公证（`flet build macos --macos-distribution developer-id ...`），以及 Windows 的代码签名证书。
