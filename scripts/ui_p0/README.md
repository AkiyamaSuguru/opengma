# UI P0：技术验证

这几个脚本用来在你的 Mac 上验证界面方案中还不确定的几点，结果决定 P2（界面框架）的具体做法。它们不属于 GMA 库，验证完可以不合并到主分支。

所有命令都在仓库根目录运行。`--with` 只是临时装上需要的包，不会改动 `pyproject.toml`。

| 脚本 | 验证什么 | 命令 |
| --- | --- | --- |
| `p0_linechart.py` | Flet 原生 LineChart：大量数据点的流畅度、悬停读数、图例开关、横轴缩放、XPS 横轴反向 | `uv run --with flet-charts==1.0.5 python scripts/ui_p0/p0_linechart.py` |
| `p0_window.py` | 按屏幕比例的窗口尺寸、同一进程换窗、关闭工作区回到启动器 | `uv run python scripts/ui_p0/p0_window.py` |
| `p0_matplotlib.py` | 出版图预览：MatplotlibChart 与导出图片的对比 | `uv run --with flet-charts==1.0.5 python scripts/ui_p0/p0_matplotlib.py` |
| `p0_netcdf.py` | 含中文名称的项目文件能否写入并原样读回 | `uv run --with xarray --with "h5netcdf[h5py]" python scripts/ui_p0/p0_netcdf.py` |

### 一次运行全部（Mac）

```bash
bash scripts/ui_p0/run_mac.sh                     # 全部
bash scripts/ui_p0/run_mac.sh window matplotlib   # 只运行其中几项：env netcdf tests linechart window matplotlib
```

依次记录系统和显示器信息、安装依赖、运行 NetCDF 检查和单元测试，再依次打开三个窗口（关掉一个才会打开下一个）。LineChart 和换窗两个窗口打开后会先自动测速（环境变量 `P0_BENCH=1`），测完停在那里，可以继续手动操作。终端输出和测速结果都写入 `scripts/ui_p0/results/`：

| 文件 | 内容 |
| --- | --- |
| `env.log`、`netcdf.log`、`tests.log` 等 | 每一项的终端输出 |
| `linechart_bench.txt` / `.json` | 各组数据首次显示、缩放、平移、图例开关的用时（中位数）及原始记录 |
| `window.txt` | 屏幕尺寸、默认窗口尺寸、换窗用时 |
| `mpl_*.png` | 出版图对话框中导出的图片 |

LineChart 自动测速中每一步记两种时间：Python 端准备数据并发出更新的用时；以及界面完成第 1、第 3 帧布局的时间（发出更新后连续改变一个 1 像素控件的宽度，等界面回报尺寸变化，第 3 帧包含了前面帧的绘制）。后者减去“空闲（基准）”，约等于界面处理这次更新的时间。

## 已经在 Linux 无头浏览器中看到的情况

我在开发环境里用 Flet 的网页模式加无头 Chrome（软件渲染，比真机慢）跑过前三个脚本，`p0_netcdf.py` 直接运行：

- **LineChart**：5 条 XRD 叠加、每条 8 001 点（共 40 005 点），不抽稀。
  - 首次显示：准备数据约 0.3 s，发送到界面约 2–3 s。
  - 缩放：如果每次都重新发送点，一步要 0.5 s 以上。改成“只改范围”，并把曲线数据标记为隔离更新（`is_isolated`，Flet 不再逐点比较）后，一步约 60 ms。
  - LineChart 不会裁掉坐标范围以外的曲线，所以脚本把图表放进裁剪容器，坐标轴和网格线在图表外面自己画。
  - 悬停时的提示框、以及状态栏中的读数都正常。
- **MatplotlibChart**：它会把 figure 拉伸到控件大小，字号和线宽相对图面变小，与导出的 3.2 × 2.4 in 图不一致。导出的 PNG 放进 InteractiveViewer 则和最终文件完全一致，也能缩放查看细节。所以出版图对话框我倾向于用后者，请你在 Mac 上对比确认。
- **NetCDF**：中文样品名、中文分峰名、中文属性值、JSON 元数据、不同点数的谱图都能原样读回。另外发现 h5netcdf 现在需要显式安装 h5py（`h5netcdf[h5py]`），P1 的依赖会这样写。
- **换窗**：网页模式没有窗口，这一项只能在 Mac 上验证。

## 请你在 Mac 上看的内容

### P0-1 LineChart

1. “XRD · 5 条叠加”、步长 0.01°（40 005 点）首次显示要多久？界面会不会卡住？
2. 在图上滚动滚轮缩放、用触控板左右滑动平移，是否跟手？窗口下方会显示每一步的耗时。
3. 悬停时提示框和下方的读数是否跟手？
4. 点击图例隐藏、显示曲线是否及时？
5. 步长改为 0.005°（每条 16 001 点）后，以上几项如何？
6. “XPS C1s”：横轴是否从高到低，刻度数值是否正确？
7. 关掉“曲线数据隔离更新”，缩放时慢了多少？
8. 打开“悬停提示带横轴值”后，首次显示慢了多少？
9. （可选）“显示点数”中的两种抽稀和“重新筛选点”，与默认的“全部（不抽稀）+ 只改范围”对比。

### P0-2 换窗

1. 读到的屏幕尺寸是否与系统设置中“看起来像”的分辨率一致？
2. 启动器打开时是否居中；左上角的红黄绿按钮是否正常；拖动顶部灰色区域能否移动窗口；能否缩放？
3. 进入工作区、回到启动器时是否闪烁？用时多少？
4. 工作区中点红色按钮是否回到启动器；关闭开关后是否直接退出；在启动器中点红色按钮是否退出？

### P0-3 出版图预览

1. 左右两边的字号、线宽比例是否一致？Times New Roman 是否正确显示？
2. 右边用触控板缩放、拖动是否顺手？

### P0-4 NetCDF

终端最后一行是否为“全部通过”。

## 怎么反馈

把每个脚本窗口下方的耗时文字（或截图）和上面各项的结果发给我即可；用 `run_mac.sh` 运行时，`scripts/ui_p0/results/` 中的文件已经包含了耗时。
